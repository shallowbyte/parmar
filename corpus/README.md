# `corpus/` — the PG-19 corpus tiers

Every measurement in this repository was taken against these files.

**The `.txt` files themselves are not committed** — they total about 5.3 GB. What *is* committed is one `.meta.json` per tier recording the byte count, document count and sha256, so a rebuilt corpus can be verified byte-for-byte against the one that produced the published results.

## How to rebuild

```bash
python build_corpus.py --tiers "64MB,256MB,1GB,4GB" --out ./corpus/
python build_corpus.py --verify-only --tiers "64MB,256MB,1GB,4GB" --out ./corpus/
```

The builder is idempotent: a tier whose file and sha256 already match its `.meta.json` is skipped rather than refetched.

## Why each tier is a standalone corpus

Each file is cut at a **document boundary past its target size**, not truncated at an exact byte count. So a tier is a complete, valid corpus in its own right rather than a prefix of the next one, and no tier ends with half a book. Document order is shuffled once with a fixed seed (`20240517`) before accumulation, so the tiers are not correlated with publication date or any other dataset-native ordering — and the shuffle is reproducible.

## Source

`deepmind/pg19` (Apache 2.0) — Rae et al. 2019, *Compressive Transformers for Long-Range Sequence Modelling*, [arXiv:1911.05507](https://arxiv.org/abs/1911.05507).

Note that `datasets.load_dataset("deepmind/pg19", streaming=True)` **does not work** — the Hub repo carries only a loading script and file lists, has no parquet, and its `refs/convert/parquet` branch has no data either, while loading scripts were removed in `datasets` 3.0. `build_corpus.py` fetches the books directly from the public GCS bucket the script points at.
